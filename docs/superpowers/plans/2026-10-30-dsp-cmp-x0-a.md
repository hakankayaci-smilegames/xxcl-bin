# DSP CMP X0,A Comparison Implementation Plan

**Goal:** Make the GP DSP compare the actual signed 24-bit X0 operand with the 56-bit A accumulator.

**Evidence:** During the guest wait, the DSP reads command `3` into X0 and compares it with A=`0`. The current CMP code sign-extends X0 but substitutes zero for its actual middle word, sets Z, and branches as though `3 == 0`.

**Approach:** Preserve the existing 56-bit subtract/flag and parallel-transfer behavior, placing X0 itself in the middle accumulator word and sign-extending it into the top word. DSP56300 CMP subtracts the sign-extended source from the destination without storing the result: https://www.nxp.com/docs/en/reference-manual/DSP56300FM.pdf

**Verification:** Use actual DSP instruction fixtures to test zero versus positive X0, equal nonzero operands, and a negative source; verify A and X0 are unchanged. Run all tests and a fresh two-launch runtime, then determine the guest's next execution point without forcing completion flags.

**Files:** `xbe-inspect/src/kernel/apu_dsp.cpp`, `xbe-inspect/tests/apu_dsp_contract_tests.cpp`, and runtime status documentation.

**Result:** Positive, equal nonzero, and negative source cases pass alongside the full suite. A fresh two-launch game run advances DSP execution from the former branch to unsupported `PC=0x066` (`0x0A0480`). The guest wait and first render remain unproven.
